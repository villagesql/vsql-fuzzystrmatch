## Code Integrity

- [x] All pointer dereferences from VEF structs are protected.
  Evidence: Every impl function checks `->is_null` before accessing
  `->str_value`, `->str_len`, or `->int_value`. All 9 functions verified.

- [x] Off-by-one check: No binary parsing. String output uses
  `code.size() > result->max_str_len` before `memcpy`. Buffer sizes registered
  are sufficient: soundex=4 (output always 0 or 4), metaphone=64
  (user-supplied max_out capped by buffer check), dmetaphone/alt=7
  (kDMetaphoneMaxLen=6, resize enforces this).

- [x] Result types use correct SDK constants.
  Evidence: `VEF_RESULT_NULL`, `VEF_RESULT_VALUE`, `VEF_RESULT_ERROR`
  throughout. No deprecated `IS_NULL`, `IS_VALUE`, `IS_ERROR` aliases.

- [x] All STRING returns set `actual_len`.
  Evidence: `soundex_impl`, `metaphone_impl`, `dmetaphone_impl`,
  `dmetaphone_alt_impl` all set `result->actual_len = code.size()`.

- [x] No encode/decode functions (VDF-only extension, N/A).

- [x] Error messages are informative.
  Evidence: All error paths name the function and the violated constraint,
  e.g. `"levenshtein_cost: costs must be non-negative"`,
  `"metaphone: max_output_length must be > 0"`,
  `"levenshtein_less_equal: max_d must be non-negative"`.

- [x] `try/catch(...)` wrappers on all 9 VDF entry points.
  Evidence: `soundex_impl`, `difference_impl`, `levenshtein_impl`,
  `levenshtein_cost_impl`, `levenshtein_less_equal_impl`,
  `levenshtein_less_equal_cost_impl`, `metaphone_impl`, `dmetaphone_impl`,
  `dmetaphone_alt_impl` — all wrapped.

## Additional Correctness Notes (from Phase 3 simplification)

- Levenshtein DP uses stack arrays (`long long[256]`) instead of heap vectors;
  equal-string and empty-source fast paths added.
- `levenshtein_less_equal` and `levenshtein_less_equal_cost` now validate
  `max_d >= 0` (negative max_d previously returned wrong result silently).
- `levenshtein_cost` and `levenshtein_less_equal_cost` validate costs ≤ INT_MAX
  (prevents signed integer overflow in DP accumulation).
- `metaphone`: `max_output_length > INT_MAX` now returns an error (previously
  caused UB at the `static_cast<int>` site).
- `max_d + 1` arithmetic guarded against `LLONG_MAX` overflow.
- Two dead ternaries removed in `compute_dmetaphone` (both-arms-same-value).
